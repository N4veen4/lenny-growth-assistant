# Artifact Viewer API and Integration

## Overview
The Artifact Viewer is a dedicated UI pane (built in Lovable) designed to render long-form generated content (essays, code, HTML) separately from the main chat flow. This document outlines the API contracts and security rules the frontend should follow to integrate with the Phase 7 backend implementation.

## Artifact Data Structure
Artifacts are strongly typed and associated directly with their parent conversation.
```typescript
interface Artifact {
    id: string; // UUID
    conversation_id: string; // UUID
    title: string;
    artifact_type: "markdown" | "html" | "text";
    content: string;
    version: number;
    created_at: string; // ISO DateTime
    updated_at: string; // ISO DateTime
}
```

## Relevant API Endpoints

### 1. Generating an Artifact
**Endpoint:** `POST /api/v1/chat`
When asking for an essay, the backend automatically extracts the artifact and returns it in the response payload.
**Response snippet:**
```json
{
  "response_text": "Here is the essay you requested:\n\n*[Generated Artifact: Growth Tactics]*",
  "artifacts": [
    {
      "id": "123e4567-e89b-12d3-a456-426614174000",
      "conversation_id": "...",
      "title": "Growth Tactics",
      "artifact_type": "markdown",
      "content": "# Growth Tactics\n...",
      "version": 1
    }
  ]
}
```

### 2. Retrieving Conversation Artifacts
**Endpoint:** `GET /api/v1/conversations/{conversation_id}/artifacts`
Returns an array of all artifacts generated during a specific session.

### 3. Fetching a Specific Artifact
**Endpoint:** `GET /api/v1/artifacts/{artifact_id}`
Retrieves a single artifact by its UUID.

## Frontend Security & Rendering Guidelines
Because artifacts can contain HTML or Markdown generated by an AI, the frontend must strictly isolate the content to prevent XSS (Cross-Site Scripting) or other injection attacks.

### Rendering Markdown
- Use a safe markdown parser (e.g., `react-markdown` or `marked`).
- Ensure HTML rendering inside Markdown is disabled or heavily sanitized via libraries like `DOMPurify`.
- Preserve headers, lists, links, and code blocks for readability.

### Rendering HTML/CSS
- Generated HTML **must** be rendered inside a sandboxed iframe.
- Example configuration:
  ```html
  <iframe 
    sandbox="allow-scripts allow-same-origin" 
    csp="default-src 'self'; script-src 'none';"
    srcDoc={artifact.content} 
  />
  ```
- **Do not** allow generated content to access application credentials, parent-window data, or privileged browser APIs.
- Javascript execution within artifacts should remain disabled unless explicitly required by a specific use case.
